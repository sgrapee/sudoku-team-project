# 발표 시연용 GUI

Python 기본 `tkinter`만 사용하므로 별도 GUI 라이브러리가 필요하지 않습니다.

## 실행

저장소 루트에서 실행합니다.

```powershell
python run_gui.py
```

또는 다음 명령도 같습니다.

```powershell
python gui/app.py
```

## 시연 순서

1. 오른쪽 위에서 변형 스도쿠 예제를 선택합니다.
2. 보드에 표시된 대각선·킬러·온도계·화살표 등의 제약을 설명합니다.
3. `AI 힌트`로 사람이 사용하는 논리 기법과 설명을 보여줍니다.
   - 직접 넣은 숫자 중 정답과 다른 칸이 있으면 힌트 대신 그 칸을 빨갛게 표시합니다. 틀린 입력을 전제로 추론하면 틀린 힌트를 "확정"이라고 내게 되기 때문입니다. 칸을 고치면 빨간 표시가 사라집니다.
   - 정답이 하나로 정해지지 않는 보드(빈 보드 등)에서는 칸을 지목하지 않고 "완성할 수 없음"만 알립니다.
4. `과정 보며 풀기`로 CSP 엔진이 후보를 넣고, 제약을 전파하고, 모순이면 되돌아가는 과정을 확인합니다.
   - 탐색이 650단계보다 길면 앞·중간·끝을 골라 650단계만 재생합니다. 이때는 처음부터 "전체 N단계 중 650단계 표본"으로 표시합니다.
5. 느리게·보통·빠르게 중 재생 속도를 선택하고 필요하면 일시정지합니다.
6. 오른쪽에서 난이도·유일해 여부, 아래에서 탐색 노드·백트랙·실행 시간을 확인합니다.
   - 오른쪽 정보 영역은 화면이 낮으면 스크롤됩니다(규칙 요약은 아래쪽).
7. `결과 JSON 저장`으로 완성된 보드를 저장하고 독립 검사기로 확인합니다.
   - 저장 형식은 `independent_checker`가 읽는 `sudoku-result-v1`입니다. 엔진으로 푼 경우 탐색 통계도 함께, LLM 파싱 결과라면 적용 안 된 규칙(`unsupported`)도 함께 저장됩니다.
   - 검사: `python independent_checker/checker.py 저장한파일.json` (또는 검사기 GUI에서 파일 선택)

## LLM으로 자연어 퍼즐 불러오기 (FactChat)

자연어 퍼즐 설명을 LLM이 명세로 바꾸고, 그 명세로 백트래킹 탐색을 재생합니다.
파싱은 `parser/llm_parser`의 `parse_rules`를 그대로 쓰므로 평가(`solver_eval`)와 같은 프롬프트·검증·재시도를 거칩니다.

1. 화면 위쪽 `FactChat 키` 칸에 학교 FactChat에서 발급한 API 키를 붙여넣습니다(화면에는 `*`로 표시).
   - `Ctrl+V`, `Shift+Insert`, 입력칸 우클릭 메뉴, 옆의 `붙여넣기` 버튼을 모두 사용할 수 있습니다.
   - 환경변수 `FACTCHAT_API_KEY`가 있으면 칸을 비워 둬도 그 키를 씁니다.
   - 키는 프로그램이 켜져 있는 동안 메모리에만 있고, 파일·로그에 저장되지 않습니다.
2. `연결 확인`을 누르면 키를 확인하고 남은 크레딧과 쓸 수 있는 모델 목록을 불러옵니다.
   - 모델은 모두 FactChat을 통해 호출합니다. 이름 옆에 제공 회사가 표시됩니다(예: `gemini-3.5-flash (Google)`, `claude-haiku-5-5 (Anthropic)`).
   - 기본 모델은 평가에 쓴 `gemini-3.5-flash`입니다. 다른 모델은 동작하지만 정확도는 검증하지 않았습니다.
3. 오른쪽 `자연어 입력` → 시연용 문장(평가에 쓴 50개)을 고르거나 직접 입력 → `LLM으로 파싱`.
   - 단서 격자(9칸 × 9줄 또는 81자 한 줄)는 LLM이 아니라 코드가 꺼냅니다.
   - 지원 규칙: 대각선·킬러·온도계·화살표·샌드위치·서로 다름·짝수/홀수·부등호. 그 밖의 규칙은 적용하지 않고 알려 줍니다.
   - 해가 없는 명세는 거부하고 사유를 LLM에 알려 다시 요청합니다(최대 3회).
4. 성공하면 보드에 제약이 그려집니다. `과정 보며 풀기`로 백트래킹 탐색을 재생합니다.
   - 위쪽 `명세 보기`에서 시도별 결과, 적용 안 된 규칙, 명세 JSON을 볼 수 있습니다.
   - 시연용 문장을 고치지 않고 파싱했다면 `정답 명세 일치 ✔/✘`가 표시됩니다.

파싱 1회에 약 10~26 크레딧(gemini-3.5-flash 기준, 설명이 길수록 많음)이 키를 만든 계정에서 차감됩니다. 실측(2026-11-25): 짧은 클래식 설명(nl-001) 9.9~15.0(호출마다 다름), 긴 expert 혼합 설명(nl-035) 25.8, 평가 50개 평균 16.6. 크레딧 소진·키 오류·모델 권한 오류는 한국어 한 줄로 표시되고, 나머지 기능은 그대로 동작합니다.

## 숫자 색상

| 색상 | 의미 |
|---|---|
| 검정 | 퍼즐에 처음부터 주어진 고정 단서 |
| 파랑 | 사용자가 직접 입력한 숫자 |
| 주황 | 엔진이 탐색 중 임시로 시도한 숫자. 백트래킹으로 바뀔 수 있음 |
| 초록 | 탐색이 끝난 뒤 확정된 최종 숫자 |

## 단축키

| 키 | 기능 |
|---|---|
| `1`~`9` | 선택한 칸에 숫자 입력 |
| `Delete`, `Backspace` | 숫자 삭제 |
| 방향키 | 선택 칸 이동 |
| `F5` | 퍼즐 풀기 |
| `Ctrl+H` | 힌트 |
| `Ctrl+R` | 처음 상태로 초기화 |

GUI와 엔진·LLM 연동 모듈 연결만 확인하려면 창을 띄우지 않고 다음을 실행합니다(LLM은 호출하지 않음).

```powershell
python run_gui.py --smoke-test
```
