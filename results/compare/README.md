# 백트래킹 vs 로컬서치 비교 결과

같은 퍼즐을 백트래킹과 로컬서치(min-conflicts)에 풀게 해서 "왜 백트래킹(+ 제약 전파)인가"를 숫자로 보이는 결과다.
모든 스크립트는 저장소 루트에서 `python datagen/<스크립트>`로 실행한다.

## 파일

| 파일 | 내용 | 만드는 스크립트 |
|---|---|---|
| `runs.csv` | bench 109퍼즐(classic 40, variant 45, multi 12, unsat 12) × 백트래킹 2설정 + min-conflicts seed 3회, 제한 5초 | `compare_bench.py` |
| `givens_curve.csv` | 클래식, 단서 42/38/34/30/26개 × 8퍼즐. 백트래킹(mrv_degree/lcv/ac3) + min-conflicts seed 3회, 제한 5초 | `compare_givens_curve.py` |
| `variant_curve.csv` | 변형(킬러 5 + 온도계 + 짝수 칸 8), 단서 45/35/28/22/18개 × 4퍼즐. 백트래킹 2설정 + min-conflicts(init random/row) seed 3회, 제한 10초. `engine/compare_methods.py --suite variant --time-limit 10`과 같은 퍼즐·seed | `compare_variant_curve.py` |
| `ls_failures.csv` | min-conflicts가 못 푼 85퍼즐에서 가장 좋았을 때 남은 위반 수 (seed 0, 제한 5초) | `compare_ls_failures.py` |
| `figures/` | 아래 그래프 4장과 숫자 표 `summary.md` | `plot_compare.py` (matplotlib 필요) |

백트래킹 설정 이름은 `변수 순서/값 순서/전파`다. `mrv_degree/lcv/ac3`은 엔진 기본값(전파 있음), `static/asc/none`은 전파·휴리스틱이 없는 단순 백트래킹이다.

## 결과 요약

- **전파를 쓰는 백트래킹**은 모든 세트·단서 수에서 100%를 풀었고, 성공한 실행의 중앙값은 4~11ms다. 해 없음 12개도 모두 증명했다.
- **min-conflicts는 단서가 많을 때만 푼다.** 클래식은 단서 38개 이상 100%, 34개 62%, 30개 8%, 26개 0%다. 변형은 35개 이상 100%, 28개 42%(random)·67%(row), 22개 이하 0%다. 데이터셋 퍼즐(단서 16~27개)인 bench 세트에서는 0%다.
- 실패한 min-conflicts는 정답 근처까지도 가지 못한다. 남은 위반 수 중앙값은 클래식 5, 대각선 7, 온도계 6, 화살표 8, 킬러 12, 혼합 11이다. 5초 동안 이동 7만~10만 번(중앙값 약 9만), 재시작 3~7번을 하고도 지역 최솟값에서 벗어나지 못했다.
- **단순 백트래킹**은 단서가 적을수록 급격히 느려진다. 변형 단서 22개에서 중앙값 3.2초, 18개에서 25%다. bench 세트 정답 비율은 클래식 42%, 변형 16%, 여러 해 67%, 해 없음 50%다.
- 해 없음·여러 해 퍼즐에서 로컬서치는 판정을 내리지 못한다. 해가 없으면 끝나지 않고, 해가 여러 개여도 하나만 낸다. 백트래킹은 해가 없음을 증명하고 해 개수를 셀 수 있다.

## 해석할 때 주의

- 로컬서치 성공률은 제한 시간 근처에서 갈려서 컴퓨터 속도와 부하에 민감하다. 같은 변형 퍼즐을 다른 컴퓨터에서 돌린 `compare_methods.py` 결과는 단서 28개 min-conflicts 25%(random)·42%(row), 단서 22개 단순 백트래킹 75%로, 이 저장소의 결과(42%·67%, 100%)보다 낮았다. 무거운 작업과 같이 돌리지 않는다.
- 퍼즐 수가 적다(단서 수 단계마다 클래식 8개, 변형 4개). 성공률은 경향으로 보고, 정밀한 비교에는 쓰지 않는다.
- 시간(ms)은 컴퓨터마다 다르다. 방법끼리의 상대 비교로만 본다.
